# APK Size Reduction Specification

## Goal

Substantially reduce the direct-download local APK from its approximately 100 MB
baseline. A 20 to 30 MB result is preferred, but there is no rigid size cutoff.
All current finance, SQLite, backup and restore, chart, biometric unlock, and
offline workspace features remain unchanged.

## Release profiles

| Profile | ABI support | Audience |
| --- | --- | --- |
| `production` | `arm64-v8a` | Main APK for modern Android phones, including Redmi Note 14 4G |
| `production-compat` | `armeabi-v7a`, `arm64-v8a` | Fallback for a friend with a 32-bit Android phone |
| `offline-friends` | `arm64-v8a` | Local-only APK named `Faura` |

All profiles output signed, internally distributed APKs. `offline-friends` is a
release APK, not a development client. Preview builds retain their existing
architecture coverage.

## Implementation

- `FAURA_APP_MODE=offline` configures the local-only build. Its display name is
  `Faura`; online builds remain named `Faura Farmer`.
- `FAURA_APK_VARIANT=arm64` configures both the main and local release; `compat`
  configures the fallback.
- `expo-build-properties` writes the selected ABI list during Expo prebuild, rather than relying on an ordinary EAS environment variable.
- Optimized builds enable R8 code shrinking, resource shrinking, and compressed native-library packaging.
- An invalid APK variant stops configuration with an actionable error.
- Android `versionCode` is 3 so `com.faura.farmer.local` can replace its prior build.
- Native Android folders remain generated by Expo and are not committed.
- The local build retains the package identity `com.faura.farmer.local` and does
  not configure a server API, database schema, migration, or production environment.

## Verification

1. Validate that the resolved `offline-friends` Expo config reports `Faura`, offline
   mode, `com.faura.farmer.local`, ARM64, and no development client.
2. Build and inspect the ARM64 local release APK. It must contain only
   `lib/arm64-v8a/` native libraries and compressed `.so` entries, with no
   `armeabi-v7a`, `x86`, or `x86_64` libraries.
3. Verify the APK signature with `apksigner verify --verbose --print-certs` and
   confirm it uses the preserved EAS-managed signing certificate.
4. Install on an ARM64 Android device and verify local profile creation,
   transactions, budgets, reports, backup and restore, app locking, and offline
   persistence.
5. Record baseline and final APK sizes and largest components. If the release is
   above roughly 30 MB, inspect the largest remaining native components before
   considering any feature tradeoff.

Compressed libraries reduce the downloadable APK. Android extracts them at install time, so installed storage may not decrease by the same amount.

## Compatibility and rollback

Before sharing the ARM64 APK, verify a phone includes `arm64-v8a` in `adb shell getprop ro.product.cpu.abilist`. Provide the compatibility build only for phones that cannot install the main APK.

To roll back, remove `FAURA_APK_VARIANT` from the relevant release profile and rebuild with the same signing identity. Preserve user data and increase `versionCode` for replacement releases.
